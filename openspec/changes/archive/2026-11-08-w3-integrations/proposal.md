# Proposal

## Why

A tenant admin still needs the browser for the integration and upkeep screens of the tix web UI: webhooks and their
delivery log, external sync from Jira or OpenProject, retention and pruning, housekeeping, the trash and the audit
log. These are rarely used but they are the ones reached for when something is wrong, often from a phone.

## What Changes

- Webhooks: endpoints listed, added, edited and deleted; the delivery log filtered by endpoint and status, with
  Redeliver. A signing secret left blank is generated by the app and shown once.
- External sync: sources listed with how their last run went and what a run still lacks on the server; added and
  edited with settings, a mapping and write-only credentials; checked without saving; run now or previewed; the run
  history from the audit log. Refusals (egress, file root, missing pieces) are shown in tix's words.
- Retention: the three windows in days, a preview of what pruning would remove, and pruning after a red
  confirmation.
- Housekeeping: the tenant rules for done, cancelled and trashed tasks with what each would act on now, a pause note
  while the trash is off, a preview and a run after a red confirmation.
- Trash: trashed tasks a page at a time, each with Restore.
- Audit log: every entry newest first, narrowed by text, channel, surface, actor, action, API token and time, with
  each entry's detail beside the list on a wide window.

## Impact

- New capabilities: `webhooks`, `external-sync`, `maintenance`, `audit-log`.
- Operations bound in the parity registry (wave 3): `audit.list`, `webhook.list|put|delete|deliveries|redeliver`,
  `sync.source.list|put|delete`, `sync.run`, `retention.get|put|prune`, `housekeeping.get|put|run`. The trash uses
  `task.list`, `task.restore` and `trash.status`, already bound.
- Not in tix's API, so not in the app: a webhook test ping, reading back a secret tix generated (the HTTP API drops
  it), and deleting a trashed task for good (only housekeeping's trash rule does).
